# AfterBuy – Data Dictionary

This document describes every column in each dataset generated by the AfterBuy synthetic data generator.

> ⚠ **All data is SYNTHETIC / SIMULATED.** No real customer information is used.

---

## 1. products.csv

Contains 100 product records representing the product catalog.

| Column           | Data Type | Description                                                        |
|------------------|-----------|--------------------------------------------------------------------|
| `product_id`     | String    | Unique product identifier. Format: `PROD-XXXX` (e.g., PROD-0001). |
| `product_name`   | String    | Full product name including brand, model line, and model number.   |
| `brand`          | String    | Manufacturer brand name (e.g., Dell, Samsung, Sony).               |
| `category`       | String    | Product category. One of: Laptops, Smartphones, Headphones, Smartwatches, Tablets, Speakers, Monitors. |
| `launch_date`    | Date      | Product launch date in `YYYY-MM-DD` format. Range: 2022-01-01 to 2024-06-30. |
| `price`          | Integer   | Base retail price in INR (₹). Rounded to nearest 10.              |
| `warranty_months`| Integer   | Standard warranty period in months. Varies by category (6–36 months). |

---

## 2. sales.csv

Contains 1000 sales transaction records.

| Column           | Data Type | Description                                                        |
|------------------|-----------|--------------------------------------------------------------------|
| `sale_id`        | String    | Unique sale identifier. Format: `SALE-XXXXX` (e.g., SALE-00001).  |
| `product_id`     | String    | Foreign key → `products.product_id`. References the product sold.  |
| `purchase_date`  | Date      | Date of purchase in `YYYY-MM-DD` format. Always after the product's `launch_date`. |
| `selling_price`  | Integer   | Actual selling price in INR (₹). May differ from base price by ±10% (discounts/markups). |
| `sales_channel`  | String    | Channel through which the sale was made. One of: Online, Retail Store, Authorized Dealer, Company Website, Marketplace. |
| `customer_region`| String    | Geographic region of the customer. One of: North, South, East, West, Central. |

---

## 3. warranty_claims.csv

Contains 400 warranty claim records filed by customers.

| Column           | Data Type | Description                                                        |
|------------------|-----------|--------------------------------------------------------------------|
| `claim_id`       | String    | Unique claim identifier. Format: `CLM-XXXXX` (e.g., CLM-00001).  |
| `sale_id`        | String    | Foreign key → `sales.sale_id`. References the original sale transaction. |
| `product_id`     | String    | Foreign key → `products.product_id`. References the claimed product. |
| `claim_date`     | Date      | Date the warranty claim was filed in `YYYY-MM-DD` format. Always after the `purchase_date`. |
| `claim_reason`   | String    | Description of the issue reported (e.g., "Battery draining fast", "Screen flickering"). |
| `claim_status`   | String    | Current status of the claim. One of: Approved, Rejected, Pending, Under Review. |
| `warranty_valid` | String    | Whether the claim falls within the warranty period. Values: `Yes` or `No`. Calculated based on purchase date + warranty months. |

---

## 4. repairs.csv

Contains 300 repair service records linked to warranty claims.

| Column               | Data Type | Description                                                        |
|----------------------|-----------|--------------------------------------------------------------------|
| `repair_id`          | String    | Unique repair identifier. Format: `REP-XXXXX` (e.g., REP-00001). |
| `claim_id`           | String    | Foreign key → `warranty_claims.claim_id`. References the originating warranty claim. |
| `product_id`         | String    | Foreign key → `products.product_id`. References the product being repaired. |
| `repair_date`        | Date      | Date repair work began in `YYYY-MM-DD` format. Always 1–14 days after the `claim_date`. |
| `repair_cost`        | Integer   | Cost of the repair in INR (₹). Range: ₹200–₹15,000. Follows a log-normal distribution (most repairs are lower cost). |
| `repair_duration_days`| Integer  | Duration of the repair in calendar days. Range: 1–30 days. |
| `repair_status`      | String    | Outcome of the repair. One of: Completed, In Progress, Pending Parts, Returned Unrepaired. |

---

## 5. defects.csv

Contains 500 defect records identified in products.

| Column           | Data Type | Description                                                        |
|------------------|-----------|--------------------------------------------------------------------|
| `defect_id`      | String    | Unique defect identifier. Format: `DEF-XXXXX` (e.g., DEF-00001). |
| `product_id`     | String    | Foreign key → `products.product_id`. References the product with the defect. |
| `claim_id`       | String    | Foreign key → `warranty_claims.claim_id` or `N/A`. Links to a warranty claim if applicable (~70% are linked). |
| `defect_category`| String    | Type of defect. One of: Battery, Display, Hardware, Software, Connectivity, Charging, Audio. |
| `severity`       | String    | Defect severity level. One of: Low, Medium, High, Critical. Distribution is weighted (Low 30%, Medium 40%, High 20%, Critical 10%). |
| `defect_date`    | Date      | Date the defect was reported in `YYYY-MM-DD` format. Always after the product's `launch_date`. |
| `repeat_failure` | String    | Indicates if the same product has had a previous defect. Values: `Yes` or `No`. |

## Entity Relationships

```
products ──────┬───────────────────────────────────┐
  (product_id) │                                   │
               ▼                                   ▼
            sales                              defects
         (sale_id,                          (defect_id,
          product_id)                        product_id,
               │                             claim_id → N/A or CLM-*)
               ▼
       warranty_claims
         (claim_id,
          sale_id,
          product_id)
               │
               ▼
           repairs
         (repair_id,
          claim_id,
          product_id)
```

### Relationship Summary

| From → To                        | Relationship | Description                                    |
|----------------------------------|--------------|------------------------------------------------|
| `sales` → `products`            | Many-to-One  | Many sales reference one product               |
| `warranty_claims` → `sales`     | Many-to-One  | Many claims can reference the same sale         |
| `warranty_claims` → `products`  | Many-to-One  | Many claims reference one product               |
| `repairs` → `warranty_claims`   | Many-to-One  | Many repairs can reference the same claim       |
| `repairs` → `products`          | Many-to-One  | Many repairs reference one product              |
| `defects` → `products`          | Many-to-One  | Many defects reference one product              |
| `defects` → `warranty_claims`   | Many-to-One  | Optional link — some defects have no claim      |

---

## Data Quality Notes

- All IDs are unique within their respective datasets.
- All foreign keys reference valid existing records.
- All dates are logically ordered (launch → sale → claim → repair).
- Prices and costs are always positive.
- `warranty_valid` is computed — not hardcoded — based on the purchase date and warranty period.
- Random seed `42` ensures reproducibility: re-running the generator produces identical data.
